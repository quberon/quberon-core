# viz/ - deterministic evidence renderers

No figure here is hand-authored and none invents a number. Every SVG
in viz/evidence/ is generated by viz/evidence/render.py from committed
evidence files, and every value in it is read from the cited source at
render time. A figure that cannot name the file it came from is
decoration; these can.

## Figures

    python3 viz/evidence/render.py --repo-root . --out viz/evidence

- fleet-timeline.svg - fleet-sim scenario trace as a timeline, from
  fleet-sim/run.py's scripted scenario (fleet-sim/fleet_sim.py),
  including its trace_sha256 and observed_verdict. Band: SIMULATED.
- loadtest-percentiles.svg - median/p95/p99 per scenario from
  loadtest/results/attempt{1,2,3}.json. All three attempts are plotted
  per scenario (colour per attempt, line median->p99), so the spread
  between runs is visible rather than one flattering run. Band:
  MEASURED-ON-HOST (real HTTP on this host to the simulated app; the
  JSON claim_scope governs - not a physical or real-time stop-time
  claim).
- adversarial-summary.svg, adversarial-postmerge.svg,
  adversarial-hand.svg - one figure per
  research/adversarial/results/*summary*.json: per-class invariant
  violations (bar), cases, rejected, accepted_in_error, worst severity,
  and escape counts counted from that file's escapes[] list by class.
  Band: SYNTHETIC (template corpus; same-author validator - weak
  evidence, as the source evidence itself states).
- qip-traceability.svg - QIP-v0.1.md section-11 grid: all 34
  requirements, with all 18 UNIMPLEMENTED requirements marked
  "GAP - UNIMPLEMENTED (NOT TESTED)" in red rows. Traced rows name a
  W4-N4 test ID; a trace is not a pass claim and no QIP conformance
  class is claimed. Band: NOT TESTED.

## Provenance (embedded in every SVG)

Each SVG carries, in <metadata> and in a visible header block:

- source path(s), exactly as read
- source sha256 (of the bytes actually read)
- git commit (HEAD at render time)
- UTC (the committer date of that commit, converted to UTC - see below)
- evidence band: MEASURED-ON-HOST, SIMULATED, SYNTHETIC or NOT TESTED

## Determinism

Running the renderer twice must produce byte-identical output, as F4
and F6 proved for their artifacts. There is no wall clock and no
randomness in render.py: the embedded UTC is derived from the git
commit, not from the time of rendering, ordering is sorted/fixed, and
all floats are formatted explicitly. Proof (run at one commit):

    python3 viz/evidence/render.py --repo-root . --out /tmp/viz-a
    python3 viz/evidence/render.py --repo-root . --out /tmp/viz-b
    (cd /tmp/viz-a && shasum -a 256 *.svg > /tmp/viz.sha)
    (cd /tmp/viz-b && shasum -a 256 -c /tmp/viz.sha)   # all OK

Consequence: after a new commit lands, re-rendering updates only the
git_commit/UTC header (the evidence sources are unchanged unless the
commit changed them) - that is the figures staying true automatically.
If git is unavailable, commit and UTC are the literal "unknown".

## Staying true

Because numbers are never copied by hand, changing a committed
evidence file and re-running the command above redraws the figures
from the new evidence; no one has to remember to update a drawing
before a demo. viz/tests/test_render.py pins this: it checks the
embedded sha256 against the committed files, checks printed loadtest
triples against attempt1.json exactly, counts the QIP gaps from the
source table (34 rows, 18 UNIMPLEMENTED), counts adversarial escapes
from escapes[], verifies the fleet trace_sha256 against a fresh
scripted_scenario(), and renders twice asserting byte identity.
